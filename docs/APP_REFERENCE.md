# Application reference

## Current behaviour

The app reads PowerFactory CSVs and ZIP archives from `Input_files/` and session uploads. It is intended for desktop browser use. The MPE wordmark and always-visible uploader sit at the top of the sidebar, matching the Harmonics dashboard. The main column starts with the dashboard title and plots. A single `Mapping.xlsx` or `Mapping_*.xlsx` workbook is applied automatically; only multiple mapping candidates require a choice. The `Headers` sheet names filename-token filters. An optional `Grouping` sheet maps CSV equipment headers to groups shown on Equipment Loading and Power Factor.

Each cascading filename-token filter starts with its first available value when a new case set loads, leaving one initial case combination selected. The sidebar shows each token as checkboxes with **Select all** and **Clear all** buttons; **All cases** selects the full set. Filters cascade from left to right and apply to all five chart tabs.

Each chart tab shows all equipment choices as text-sized chips across the main content width. Unselected chips are light green; selected chips are light amber. A plain click selects one item; **Ctrl-click** adds or removes items. A new tab selection starts with its first equipment chip selected. When a grouping map is present, Equipment Loading and Power Factor show group tabs below the chart tabs; each group exposes only its mapped chips and **All cases** exposes every available chip. Group views keep the sidebar's filename-case filter. After the chips, tab-specific controls appear at the left of the settings row, with each label inline before its input. **Plot layout** and its choices sit at the far right. The layout defaults to **1 plot** and can be changed to **1×2** (one column, two rows) or **2×2** (two columns, two rows). Panels are filled automatically by plotted-point weight.

When a `Description` sheet is present, one **Case option descriptions** table appears directly below the plots and before any violation table. It shows each mapped filter heading once in bold, with its option values in bold and descriptions alongside; only values present in the loaded files are included.

Each plot has one left-aligned native Plotly case legend below it. Entries flow into rows using the rendered panel width and the longest displayed case label, so columns reflow when the browser or sidebar changes width. Full-width plots allow up to four columns; 2×2 panels allow up to two. Each displayed chart row reserves space for its deepest legend; stacked charts size independently, keeping the following section close to the last legend. Entries show only token values that vary within that panel; common token values appear once in bold after **Case options:**. Legend font size is 12 and group gaps are removed. A single-case panel uses **Selected case** as its item and shows its case options in the header. Hover retains the case-option label and X/Y names, units and values; it only adds equipment when a panel contains multiple objects, and identifies Qmin/Qmax on boundary traces. In WTG P–Q, each case has a distinct line pattern shared by its operating curve, Qmin and Qmax boundaries; the boundaries are dark grey, while the operating curve retains its case colour. The case legend entry therefore identifies its limit pattern and toggles all three traces together. Filenames, paths, metric descriptions and transforms are omitted. Chart titles identify the chart family, the equipment when a panel contains one object, and the panel number for split layouts.

**WTG P–Q** plots Q against P with optional Qmin/Qmax boundaries. **WTG Terminal Voltage** plots U against P with editable minimum/maximum guide lines (0.92/1.08 p.u.), labelled **Min =** and **Max =** and shifted right of the zero axis. **Equipment Loading** plots each loading against negative POC active interchange, marks the highest point in each panel and draws a manually adjustable red dashed reference (100% by default). **POC P–Q** uses the negative export convention. **Power Factor** uses sweep index by default, omits the initial sample at sweep index 0, and keeps the verified sign control.

The WTG P–Q, WTG Terminal Voltage and Equipment Loading tabs show limit-violation tables immediately below the plots. P–Q compares each reactive-power sample with the case-matched Qmin/Qmax at the same sweep row; voltage compares samples with the current minimum and maximum; loading compares the selected equipment channel with the manually set loading reference (100% by default). Equality is within the limit. Each row identifies the case and object and reports the worst excess, measured value, limit and corresponding plot-axis location; point counts are omitted. Select table rows to show their matching trace groups above; P–Q selections retain the operating curve and both case-matched boundaries. Clearing the row selection restores all currently filtered traces. Selection clears when the selected case or equipment scope changes, or when the violation rows change. These are sample comparisons, not time-based or compliance assessments. Voltage violations are not evaluated while the minimum is greater than or equal to the maximum.

The chart summary reports cases, elements, curves and panels. Downloaded CSV retains full case/source provenance. The separate plotted-sources table is removed.

Data validation is collapsed unless errors need attention. It shows input/case counts and a short issue table with severity, issue, affected-file count, one example filename and object where relevant. Identical issues are grouped so repeated export notices do not create duplicate rows. It does not repeat case IDs or full paths. With no valid cases loaded, the app shows one upload prompt instead of empty chart tabs.

Local reads, parsed data, uploads, channel catalogues, mappings, violation summaries and recent plot sets are cached within the session. CSV parsing is keyed independently from loose mapping workbooks, so changing a mapping does not reparse result files; expanded CSV bytes are discarded after parsing. Cache entry counts are bounded to limit retained upload, case and figure memory. Plot ranges and loading peaks are calculated in a single pass without building point-sized temporary lists. Non-finite CSV numbers are treated as missing samples. Local file changes are detected from path, size and modification time; uploads stay in the current session and can be removed in the uploader. No separate input-actions panel is required.

The dashboard displays existing results only. Reference lines are visual guides; it does not run PowerFactory or assess compliance.

## Known scope

PNG ZIP export is deferred. Individual Plotly figures retain their native image download controls. The app supports UTF-8 and UTF-8-with-BOM CSV input.
